# M7-F：公的支援制度の実データ収集・アプリ仮完成（作業記録）

2026-10-27 実施。M7-B〜M7-E の基盤（制度ストア・調査計画・発見パイプライン・
レビュー/公開フロー）をそのまま使い、実在する公式ページから制度候補を発見・
検証・公開した記録。新しい基盤の追加実装は、新規ホストを公式確認できるように
する `scripts/retrieve-official-sources.ts` の最小拡張（下記3-1）のみ。

## 1. 実施内容の要点

- 公式ポータル/個別制度ページの実在を Web アクセスで確認してから調査計画
  （`data/survey-plan.json`）と情報源台帳（`data/source-ledger.json`）に登録。
  推測 URL の登録はしない（404 と判明した URL は登録せず破棄した）。
- 既存 M7-D パイプライン（scan → fetch → extract）で実ページを取得し、
  INIAD API（gpt-5.4 / chat.completions）で候補を抽出（すべて未検証で保存）。
- 既存 M7-E レビュー（verify-field → approve → publish）で、重要8項目を
  根拠抜粋の本文実在・値一致チェック（機械的に強制）に通してから公開。
  人間レビューではなく **AI エージェント（actor: `AIエージェント(M7-F)`）による
  抜粋照合** であることは監査ログと本記録に明示する。本番運用前に人手の
  再確認を推奨する。

## 3. 既存仕組みの最小修正（2点）

1. `scripts/retrieve-official-sources.ts`：公式確認（状態3）の記録コマンド
   `--confirm-official` と、台帳登録済み URL の初回取得（状態2）を可能にする
   許可ホスト扱いを追加。これがないと新規ホスト（東京都・区）が
   「許可ホスト（official-confirmed）」に加わらず、パイプラインで一切
   取得できない（到達記録が無いと公式確認もできない循環だった）。
   HTTPS 必須・robots.txt・SSRF 対策・サイズ/形式制限は変更なし。
2. `lib/discovery/aiExtract.ts` / `cli.ts`：抽出方法ラベル `iniad:gpt-5.4` が
   そのまま API のモデル名として送信され 404 になっていたため、API 送信モデル
   （`gpt-5.4`）と記録ラベル（`iniad:gpt-5.4`）を分離。

## 4. 未解決事項・制約

- **東京都福祉局（fukushi.metro.tokyo.lg.jp）は取得不可**：HTML が 535〜594KB で
  既存の本文サイズ上限 500KB を超える（`too-large` で失敗記録）。既存制限は
  維持したため、018サポート・出産子育て応援事業・保育料無償化など東京都独自
  制度の主要ページはパイプラインで取得できず。東京都の公開制度は
  サイズ制限内（469KB）の子供政策連携室ページ由来の1件のみ。
- **東京都「奨学金返還支援制度」は承認済み・未公開**：公開ゲートで
  「支援種別が明確でない（kind: other。給付・減免・貸付・税のいずれでもない）」
  として拒否された（監査に `publish-rejected` として記録）。返還支援（貸付
  関連）としての分類は人手判断が必要。候補フィールドの編集コマンドは
  M7-E 未提供（M7-E ドキュメント §9 の拡張余地）。
- `discovery verify` は AI 抽出時の根拠抜粋4件が本文と不一致（表示上「要再確認」
  フラグ）を問題として報告する。公開済み制度の8項目確認はすべて本文実在の
  抜粋で行っており、公開データの根拠には影響しない。
- 相談AI のナレッジベース（M6）は調査ログ由来のため新規公開5件は未収録
  （制度一覧・シミュレーション・照合 UI には反映済み）。
- 文京区・台東区・港区のインデックスページからは候補0件（案内ページのみ）。
  個別制度ページは各区1件ずつ取得・抽出した。

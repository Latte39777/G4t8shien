### 1.2 INIAD 公式サイトで確認できた関連情報（AI-MOP について・参考）

- 東洋大学 INIAD は「AI-MOP」（AI Management and Operation Platform）を 2023 年 4 月から全学生に導入し、サポートするモデルは継続的にアップデートされている。
- AI-MOP は GPT シリーズを含む複数ベンダーの LLM へアクセスする API を提供する。無限ループ・異常アクセスの検出時に通信を自動停止する機能がある。
- トークン管理機能があり、利用者は消費トークン数を確認でき、管理者はユーザ・組織・グループ単位で月次トークン上限を設定できる。
- プログラム連携向けの JSON 応答モードがある（AI-MOP レベルの機能）。
- URL・PDF を登録すると内容を自動解析・ベクトル化してプロンプトに反映する機能がある（AI-MOP の RAG 機能）。
- API 実装のためベンダー側の学習に利用履歴は使われない。組織の管理ポリシーに基づき、会話ログを組織内の応答品質向上に利用することは可能。
- ※ api.openai.iniad.org と AI-MOP の対応関係（同一基盤かどうか）は未確認。上記は参考情報として扱い、API の仕様としては 1.1 の確認済み項目のみに依存する。

## 2. Web 検索の実現方法と制約

### 2.1 AI 生成と Web 検索の分離（原則）

- AI モデルへの質問（lib/consult/iniadAdvisor.ts）と、公式サイトの検索・取得（lib/consult/officialSource.ts）を完全に別機能として設計した。相互に import せず、外部通信経路も共有しない。
- 責務分離: API 通信（iniadAdvisor）／公式情報の取得（sourceFetch・officialSource）／情報整理（AI）／スキーマ検証（zod）／出典検証（evidence）／金額計算（lib/finance/supports.ts）／モック切替を、それぞれ別のモジュールに分ける。
- AI の役割は「情報整理」に限定する。給付額・法令・申請期限などの確定を AI の学習知識で行わない（システムプロンプトの禁止事項と replySchema の strip で強制）。
- 公式情報を取得できない場合は、既存の未確認表示（hasUnverified=true・relatedPrograms 空・checkedAt null）を維持する。

### 2.2 公式情報の取得フロー（次工程で実装するもの。M6-E では未実装）

1. 検索（search）: 公式サイト内で候補 URL を発見する。検索ヒット＝取得済みとは扱わない。
2. 取得（fetchSource）: 特定 URL の本文を取得する（robots・利用条件を遵守。自動巡回は行わない）。
3. 出典検証: lib/supports/evidence.ts の URL ポリシー（url あり・urlVerified・official のすべて）で確認済み判定。urlVerified は検証レイヤでのみ設定し、AI の生成結果では true にしない。
4. 根拠の供給: buildEvidenceContext で確認済みの情報のみを AI の材料に供給する。未確認の情報は確定材料にしない（混ぜない）。

### 2.3 制約

- web_search ツールの提供が未確認のため、AI に「検索した・公式サイトを確認した」ことをさせない。
- 取得に失敗した場合・未実装の場合は未確認表示のままとし、AI の学習知識で補完しない。
- 公式サイトの自動巡回は行わない（対象 URL の台帳管理と限定的な取得にとどめる）。
- INIAD API 側の URL / PDF 取り込み機能が chat.completions 経由で使えるかどうかも未確認のため、現時点で依存しない。
